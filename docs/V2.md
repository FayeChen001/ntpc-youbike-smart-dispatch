# v2 一站式：架構、端點與邊界

分支 `v2`。根網址 `/` 是一站式單頁，既有的角色選單移到 `/replay`；
`/gov`、`/ops`、`/citizen`、`/stage` 與**所有舊端點的行為完全沒動**，
v2 是新增的一層，隨時可以回退到 `main`。

---

## 一、三種資料模式

畫面上每一塊都掛著標籤，不讓使用者猜這個數字是哪來的。

| 標籤 | 來源 | 更新 | 用在哪 |
|---|---|---|---|
| 🟢 **即時** | 新北市政府資料開放平臺 YouBike2.0 官方 API | 官方每 5 分鐘，我們每 2 分鐘取一次 | 全市站況、容量落差、調度候選、行程規劃、加碼任務 |
| 🟣 **歷史** | 2026-01-01~06-30 共 13,324,945 筆半小時快照的預算分析 | 靜態 | 見車率／見位率分級、失效曲線、尖峰稀釋、站點分型、行政區排名 |
| 🟢 **即時推論** | 訓練好的 HistGradientBoosting 跑在即時站況上 | 隨即時資料 | 30／60／120／180 分鐘後的空滿風險 |
| ⚪ **回放** | 既有的情境回放與模型 | 手動 | 演唱會散場、放學接力等說故事情境（`/replay` 進入） |

## 二、資料流

```
新北官方 API ──每 2 分鐘──▶ app/live.py
                              ├─ 站鍵對應（站名 → 60m 經緯度 → 合成負數 sid）
                              ├─ 容量落差偵測（總格數 −(可借+可還)）
                              ├─ 全市與行政區彙總
                              └─ 即時歷史緩衝（30 分鐘分箱）
                                   └─ data/live_history.parquet（持久化，重啟不歸零）
                                            │
data/processed/obs.parquet ──▶ analytics/build_analytics.py     │
  （凍結，只讀）                  └─ data/analytics/*.json/parquet │
                                            │                    │
models/hgb_h*.joblib ───────────────────────┼────────────────────┤
  （凍結，只讀）                             │                    │
                                            ▼                    ▼
                                    app/v2api.py  ◀──  app/liveforecast.py
                                            │              （重建 FeatureContext，
                                            ▼               呼叫 pipeline/features.py
                                    app/static/v2.html      同一支 make_X）
```

**關鍵設計：即時預測不是另寫一套特徵。**
`app/liveforecast.py` 把即時歷史組成矩陣 B/S/C，然後用**訓練期產出的**站點輪廓（prof）、
站統計（st）、鄰站關係（A）、行政區編碼建一個新的 `FeatureContext`，
直接呼叫訓練時用的 `make_X`。特徵定義完全一致，`pipeline/features.py` 一行都沒改。

## 三、端點

### 即時

| 端點 | 說明 |
|---|---|
| `GET /api/v2/live` | 全市彙總 ＋ 資料來源與新鮮度狀態 ＋ 各欄位的語意說明 |
| `GET /api/v2/live/stations` | 全站精簡欄位（給地圖）。`only=no_bike\|no_dock\|gap\|inactive`、`district=` |
| `GET /api/v2/station/{sid}` | 單站：即時、歷史指標、模型預測、歷史同時段風險、500m 內替代站 |

### 模型即時推論

| 端點 | 說明 |
|---|---|
| `GET /api/v2/forecast/status` | 是否可用、已累積幾個分箱、模型來源與尺度 |
| `GET /api/v2/forecast/risk` | `kind=full\|empty`、`horizon=30\|60\|120\|180`、`min_p=` |
| `GET /api/v2/forecast/station/{sid}` | 單站各尺度的預測車數、位數與零車零位機率 |

### 歷史與建議

| 端點 | 說明 |
|---|---|
| `GET /api/v2/analytics` | 全部歷史分析彙總（見車率分級、曲線、稀釋、分型、行政區…） |
| `GET /api/v2/insights` | 即時 × 歷史交叉產生的 9 條建議，每條都帶證據、處置與口徑 |
| `GET /api/v2/method` | 模型卡（MAE、新事件 PR-AUC／召回／精確、校準）＋ 資料稽核 ＋ 與臺北對照 |

### 三端功能

| 端點 | 說明 |
|---|---|
| `GET /api/v2/ops/board` | 調度候選（送車／清運）＋ 整站無服務 ＋ 設備查修，三類分開 |
| `GET /api/v2/trip` | 出發前三方案（最快／較穩／順路集點），`from_sid=`、`to_sid=` |
| `GET /api/v2/events` | 即時事件台帳與彙總（開啟中、未指派、超過 60 分、現場已恢復待結案） |
| `POST /api/v2/events` | 立案（`sid`、`kind`、`request_id` 冪等；同站同類型未結案不重複立案） |
| `POST /api/v2/events/{id}/action` | `ack`／`assign`／`close`／`reopen`，帶 `version` 樂觀鎖 |
| `POST /api/v2/events/reset` | 清空事件台帳（獨立於共用的 `/api/reset`） |
| `GET /api/v2/rewards/board` | 動態加碼任務板 ＋ 錢包 ＋ 規則 |
| `POST /api/v2/rewards/claim` | 領取任務（帶 `request_id` 冪等） |
| `GET /api/v2/rewards/leaderboard` | 團體賽與週任務（示範資料） |

## 四、三個判斷（都是這一輪調查出來的）

### 1. 容量落差

`總停車格數 −（可借＋可還）`。此刻新北 543 站、2,134 個車柱名目上存在，但既借不到也還不了。
**見車率只看可借 ≥1、見位率只看可還 ≥1，兩者都不檢查兩邊加起來對不對得上容量。**
台北開源的 `abnormal.py` 甚至是用 `capacity - available_rent_bikes` 推算空位，
壞掉的柱位在那個算式裡會被當成可以還車。

我們**不判定根因**——可能是設備故障、保留柱位，也可能是資料延遲。

### 2. 整站無服務 ≠ 缺車

可借與可還**同時為 0**，派車過去也沒有柱位可用，必須先查修。
調度看板把這類站獨立列出，不混進送車候選。
不這樣分，野柳地質公園、猴硐火車站、牡丹車站這種設備離線站會直接霸佔調度優先序
（第一版就是這樣，容量 60 的站因為 `缺口 × 權重` 衝到優先度第一）。

### 3. 月平均會把尖峰稀釋掉

捷運江子翠站 2 號出口六月見位率 93.4%（官方分級「高」），平日早峰卻有 31.8% 的時間還不了車。
政府端同時顯示月平均與尖峰兩個數字。

## 五、誠實邊界（程式與畫面都要守）

**資料口徑**
- 所有比例都是**半小時快照比例**，不是連續中斷時長，也不是旅次成功率。
- 快照零車不等於有人借不到；替代站存在不等於使用者走得到。
- 排除雙零快照（187,472 格、69 站）與六月整月零車的 25 站，兩者都單獨統計。

**即時預測**
- 落後特徵（30／60／120 分鐘前）來自**本服務自行累積**的即時歷史。
  累積不足時為缺值，HistGradientBoosting 原生支援，模型仍可推論但**準確度下降**。
  畫面在齊全前會顯示完整度進度條。
- 站點輪廓與站統計是 2026-01~06 訓練期歷史，不是今天的。
- 2026-06 之後新增的 29 站沒有輪廓，**不做模型預測**，只給即時現況。
- 模型卡（`reports/model_eval.md`）的離線指標是在六月測試集上量的，
  **不等於即時推論的準確度**。

**調度**
- 候選清單**不是派車任務**；沒有真實車隊位置、班表與載量，**不產生 ETA**。
- 前置時間拆成新動員 15 分與在勤改道 3 分，都是情境值，需派工紀錄校準。

**行程規劃**
- 直線距離乘繞路係數估算，**不是路線導航**，沒有真實路網與號誌。
- 到站風險是「到站當下無位可還的機率」，不等於旅次失敗率。

**獎勵**
- 點數、優惠券、合作商家、排行榜對手、兌換目錄**全部是示範**，兌付尚未取得。
- 官方友愛接力的日均發券 17,323 張與見車率 +4.62%、見位率 +1.52% 是**官方公布數字**，
  不是我們驗證的。

**通知**
- 頁內提示**不是手機背景推播**。`sw.js` 只有快取，沒有 push 與 notificationclick。

**與台北的比較**
- 台北的算法可能帶容忍台數與容忍時間參數，我們是純快照比例，
  兩者不是同一個演算法，只能當量級參考。
- 對見車率的批評只針對**指標涵蓋範圍**，不是說台北算錯。

## 六、跑起來

```bash
export PATH=$HOME/Library/Python/3.9/bin:$PATH
python3 analytics/build_analytics.py          # 約 51 秒，只在改口徑時需要
python3 -m uvicorn app.server:app --host 127.0.0.1 --port 8790
python3 tests/test_v2.py                      # 164 項；預設打 8790，對 8787 會拒絕執行
open http://127.0.0.1:8790/v2
```

改 `v2.html` 之後**一定要驗 inline script 的語法**，否則整頁 JS 會掛掉：

```bash
python3 -c "import re;s=open('app/static/v2.html',encoding='utf-8').read();open('/tmp/v2.js','w').write(re.findall(r'<script>(.*?)</script>',s,re.S)[-1])" && node --check /tmp/v2.js
```

測離線降級路徑（官方 API 打不通時）：

```bash
YB_LIVE_URL="http://127.0.0.1:9/nope" python3 -m uvicorn app.server:app --port 8792
```

## 七、部署

`./deploy.sh`。除了原本的程式與模型，v2 另外需要：

- `data/analytics/`（三個檔）— 缺了 `/api/v2/analytics` 會回 503，整頁載不出來
- `data/live_history.parquet` — 帶上去線上就不用從零累積兩小時的落後特徵
- `analytics/`、`tests/` — 為了線上能重算與複驗

驗收比對 md5，不是看時間戳；服務跑在 **port 80** 不是 8787。細節見 `docs/DEPLOY.md`。
